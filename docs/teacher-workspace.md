# 教師填答工作台（前端試做版）

## 開啟方式

在 Visual Studio 2022 啟動既有 `EarlyInterventionCare.Api` 專案後，使用與 Swagger 相同的主機及連接埠：

- 教師入口：`/?role=teacher`，按「預覽教師填答工作台」。
- 直接查看：`/teacher-workspace.html`。
- 預設 HTTPS 啟動設定範例：`https://localhost:7127/teacher-workspace.html`。實際以 Visual Studio 顯示的位址為準。

ASP.NET Core 已提供 wwwroot 靜態檔服務，不必新增前端框架或修改專案啟動設定。原本獨立 HTML、Figma 文件及分段設計稿保留於專題資料夾。

## 本次加入

- `wwwroot/teacher-workspace.html`：任務首頁、問卷填寫、示範完成與填寫協助。
- `wwwroot/css/teacher-workspace.css`：延續登入頁色票、院名與識別、白色卡片與電腦／窄螢幕排版。
- `wwwroot/js/teacher-workspace.js`：SNAP-IV 26 題及克氏行為量表 14 題、各自的四／三個選項、進度、填表人與日期、漏填檢查、同頁草稿及提交確認。
- 登入頁教師分頁新增獨立的預覽入口，既有授權碼輸入、驗證畫面、QR 示意與 API 不變。

SNAP-IV 題目依三個題組排列，仍在同一張可捲動表單內。Figma 文件的三張題組 Frame 是設計拆分，尚未改成實際分頁。

## 目前的資料與授權邊界

這是公開可查看的前端預覽，**不是登入成功後的受保護工作台**。畫面中的個案為固定虛構資料，不代表已取得家長同意或任何正式授權。入口不會將非空白授權碼當成成功驗證。

前端不呼叫正式保存／提交 API。示範送出只更新本頁畫面，不會消耗後端授權。草稿、姓名、日期及答案僅暫存在頁面記憶體，不寫入 localStorage、sessionStorage 或資料庫；重新整理、離開或關閉後清除。請使用虛構資料體驗。

正式版規則仍是：授權不限時，指定任務全部提交成功或家長撤銷後失效。實際有效狀態必須由後端判斷，不能用前端完成計數取代。現有 `/teacher/test-form` 僅接受兩題固定測試資料，不可把完整量表答案映射到該接口。

## 建議下一步順序

1. **先確定授權與任務規格**：一個授權對應哪位幼兒、哪些問卷及版本；確認教師能看到的最少辨識資料。由家長身分與同意流程產生授權，不讓教師自行選擇個案。
2. **建立授權驗證與任務查詢接口**：驗證授權碼／Token，回傳被指派的問卷與允許顯示的幼兒資料；無效、已使用、撤銷時拒絕。為成功驗證建立適當的受保護會話，避免將 Token 寫入瀏覽器持久儲存或日誌。
3. **建立問卷模板與草稿保存**：保存 SNAP-IV／克氏題目、選項與版本，按授權任務讀取／寫入草稿。後端核對題號、選項、填表人與日期，支援中斷後接續填寫。
4. **建立正式提交**：每份問卷提交後鎖定；只有伺服器確認保存成功，前端才顯示成功。整組指定任務完成後，由後端使授權失效；處理重送、撤銷與提交競爭，並保存操作紀錄。
5. **最後串接醫療端**：讓有權限的醫療人員調閱保存的答案，並再完成持久化、權限與整合驗證。

第一個最適合做的整合情境是「家長建立單一虛構個案授權 → 教師驗證 → 填一份 SNAP-IV → 草稿接續 → 正式提交 → 原授權拒絕再次提交」，再擴充多份問卷任務。醫療判讀與計分由後續確認的專業規格處理，本前端沒有提供診斷結果。

## 電腦版驗收基準

後續頁面統一以瀏覽器內容區 1440 × 900 CSS px 設計與驗收，不含瀏覽器工具列。教師工作台固定左側選單和上方醫院識別，主內容可用高度為 820px。首頁、協助頁及完成畫面在此尺寸完整顯示；兩份長問卷在主內容區內垂直捲動，所有題目與底部操作保留，沒有橫向溢出。

實測結果：文件寬高 1440 × 900；首頁與協助頁的主內容 clientHeight/scrollHeight 均為 820/820；SNAP-IV 與克氏表單分別在主內容內捲動；提交確認視窗及單份／全部完成畫面均落在可視區內。切換頁面重設主內容捲動位置。

獨立 HTML、Figma 分段 HTML 及 Markdown 已同步套用此布局，Figma 電腦版 Frame 均為 1440 × 900，長內容應以 Frame 內捲動呈現。
