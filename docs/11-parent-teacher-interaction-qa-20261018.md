# 家長／教師操作體驗與授權狀態驗收

日期：2026-10-18。基準分支 `feature/case-guardian-management`，本輪前基準 Commit `4064af4`。
本輪依使用者指示保存至功能分支；確切提交編號以 Git log 與推送回報為準。

## 本輪修正

### 家長 account 模式

- 修改姓名／綁定對話框自動聚焦輸入欄位。
- 純空白姓名或邀請碼不送 API，提示必填並聚焦欄位。
- API 錯誤時聚焦錯誤訊息；版本衝突不覆寫資料，保留重新載入入口。
- 關閉或 Escape 離開未儲存表單時，使用系統內確認對話框，可選繼續編輯或放棄。
- 表單請求處理中禁止透過關閉／Escape 離開；有未保存輸入或正在處理時保留 `beforeunload` 防護。
- 登出流程先等待家長端的離開判斷，避免使用者取消離開但憑證已提前清除。

### 教師 authorized 模式

- 草稿 API 即使回 HTML 401／403，仍保留狀態碼，工作台立即停止操作、清除題目及記憶體草稿，提供重驗入口。
- 任務重查、草稿保存／重載與提交均處理 401／403，不再只顯示短暫提示。
- 增加提交執行中旗標，防止同時執行兩次提交。
- 提交回執必須對應目前 taskId／版本，並有 responseId、有效時間及有效 Grant 狀態；不完整回執不顯示成功，保留同一次提交供重試。
- 第一份提交後若 Grant 仍為 ACTIVE，提供返回其他待填問卷；只有 USED 才顯示授權已完成。
- 成功提交立即更新任務待填數並清除上次錯誤提示。
- 不修改共用 Controller、RBAC、Entity、Migration 或資料庫；現有 `/api/dev` 接口仍不是正式跨模組整合完成的證明。

## 限制與後續

- 原生 `window.confirm` 在內嵌瀏覽器驗收時造成操作阻擋，因此改為系統內 `<dialog>`，並在 Chrome 實際驗證保留／放棄兩條路徑。未將原生確認失敗當成功案例。
- `beforeunload` 已保留，但本輪未完成關閉分頁／重新整理時瀏覽器原生提示的互動驗收，不列為通過。
- 錯誤授權碼的正式入口、真實 MySQL 的 Session 撤銷／競爭條件、家長正式問卷 API、正式同意書、SMS／Email 及跨模組 RBAC 仍需後續整合；本輪未宣稱完成。
- 瀏覽器模擬的授權失效只證明前端處理，不能替代後端撤銷與提交交易驗收。
- 本輪成果隨功能分支提交／推送，不合入 main；不套用任何 Migration。
