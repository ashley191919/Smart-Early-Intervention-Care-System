# 第一階段 C 模組收尾藍圖

更新日期：2026-10-06。依使用者要求，優先完成原始「第一階段分工.md」的 C：Teacher Token、QR、Audit，再擴充第二階段表單管理。此清單取代先前「下一步先做草稿」的排序；既有前端、模型與 migration 保留。

## 範圍與較新決議

原始分工的限時／EXPIRED 規劃已由後續使用者確認取代：教師授權不限時，全部指定任務提交後 USED，或由家長撤銷為 REVOKED。會話可到期，目前開發版 8 小時後重驗仍有效的授權碼，不能視為授權過期。

C 負責教師授權、最低必要任務存取、邀請交付、操作紀錄與整合測試；A 的一般登入／OTP 與 B 的一般角色權限不由 C 重做。正式家長授權須整合 A/B 的可信身分、個案關係與同意資料，目前尚未取得其實作接口，不宣告整組完成。

## 收尾順序

| 順序 | 第一階段工作 | 現況／完成標準 |
| --- | --- | --- |
| 1 | 驗收 MySQL 教師授權與任務查詢 | 已實作並通過獨立測試；待使用者本機確認產碼、驗證、撤銷、登出、重啟保存 |
| 2 | 授權交付：連結與 QR Code | 尚未完成；建立授權後能交付邀請，開啟／掃描後進入同一驗證流程；憑證不進日誌或瀏覽器持久儲存。正式外部掃描另需可到達的網站網址，不能宣稱 localhost QR 可由手機連上 |
| 3 | Audit Log 持久化 | 共用介面與記憶體紀錄已有；MySQL 保存尚未完成。補 migration、事件寫入及受保護查詢，重啟後保留；不保存碼、會話、答案或敏感個案內容 |
| 4 | 最小「提交後失效」整合 | MySQL 工作台尚無提交 API；先以既有單一虛構 SNAP-IV 任務完成必要的答案驗證、原始答案保存、去重、任務 SUBMITTED 與 grant USED，同一交易完成。兩題舊記憶體測試不當作本項已完成 |
| 5 | A/B 正式建立授權對接 | 待身分與權限接口；確認已登入且已綁定家長、可信同意與指定任務，才能建立／撤銷；未完成前維持明確 Development 測試入口 |
| 6 | 安全與整合驗收 | 錯誤／撤銷／已使用授權拒絕、教師不能取得未授權個案或任務、並行提交與撤銷、重啟保存、敏感憑證不洩漏、正式環境禁用測試入口；完整角色測試需 A/B 可用 |
| 7 | 保存與交付 | 本機驗收通過後分段提交推送，提供接口、測試與示範流程；最新 MySQL 授權改接目前尚未提交推送 |

第 4 項僅為證明動態授權生命週期的最小端到端流程，不一次擴充完整表單平台。正式授權對接可在 A/B 提供契約後提前進行；不能用模擬身分宣稱正式驗收完成。
