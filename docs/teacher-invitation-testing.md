# 教師邀請連結與 QR Code 驗收

日期：2026-10-06。MySQL 授權節點已經使用者驗收並保存推送（8ef7f33）。本次新增開發測試邀請交付，不代表正式家長同意、手機網站部署或瀏覽器內建相機掃描已完成；不用新增 migration。

使用者驗收紀錄：2026-10-06 回報本機驗收成功，並要求保存推送此節點。下一步為操作紀錄持久化。

## 操作

1. 停止舊的 VS2022 專案服務，重新建置並啟動 Development 專案。
2. 開啟與該網站同一主機／連接埠的 `/?role=teacher`，按 Ctrl+F5 強制重新整理，取得新版頁面及資源。
3. 展開「試做畫面預覽與測試授權」，按「產生測試授權碼並填入」。新視窗顯示 QR Code、邀請連結、複製與開啟按鈕。
4. 按「複製邀請連結」，貼到同一台電腦的新分頁；或按「開啟邀請連結」。連結會帶入授權碼，並清除網址中的 fragment；按「驗證授權碼」才會向後端驗證，成功後取得指定 SNAP-IV 任務。它不是免驗證直接開啟工作台。
5. 關閉視窗後可按「查看邀請連結與 QR Code」重看本頁剛建立的邀請。重新整理／離開後不保留明碼；後端不提供查閱既有明碼或重新取得 QR 的接口。
6. 用既有撤銷步驟撤銷本次 grant，再開啟原邀請連結並按驗證，應顯示「授權無法使用」。再次產生新碼會撤銷舊開發授權與會話，因此舊連結／QR 一起失效。

## 本機限制

目前網址限定 localhost／127.0.0.1／IPv6 loopback，同一台電腦可測試。手機即使成功辨識 QR，也會把 localhost 當成手機自己，無法連到你的電腦。手機實際開啟的端到端驗收須等可達的測試網站與 HTTPS 網址準備好；本次沒有開放網路、變更防火牆或部署。

登入頁的「掃描 QR Code」仍是相機尚未啟用的畫面預覽。本次完成的是產生可辨識 QR 與邀請網址；不是網頁內攝影機掃描器。

## 設計與證據

- `POST /api/dev/teacher-workspace/grants` 沿用原回應，新增 invitationUrl、qrCodeDataUrl（PNG data URL）；同一授權只在建立時交付明碼。
- 邀請使用 `/?role=teacher#code=...`，憑證在 fragment，不進 HTTP URL／query。頁面同步讀取後立即 replaceState 清除，僅帶入輸入欄，不自動建立登入會話；不寫 localStorage／sessionStorage。
- 同源本機 origin 驗證在建立授權前完成，非本機 Host 拒絕；QR 由專案內 QRCoder 1.8.0 產生，不傳送憑證至外部 QR 服務。[QRCoder 官方套件](https://www.nuget.org/packages/QRCoder/1.8.0)。
- HTML 與授權 API 禁止快取；新增 CSS／JS 版本參數，並兼容舊版 HTML 暫時未更新的情況。
- build：0 警告、0 錯誤。既有 HTTP 授權／撤銷／登出檢查通過。
- `tests/TestTeacherInvitation.py`：用獨立 QR 解碼器確認 PNG 真正包含完整相同邀請網址，fragment 與原碼一致、有效碼可驗證、撤銷後 401、nonlocal Host 400、回應 no-store；不列印碼或 cookies。測試用 pillow／zxing-cpp，不是網站運行依賴。
