# 試做版登入頁

依 Figma「試做版」的家長登入（第二版）、教師登入（第二版）與醫護登入畫面實作。共用卡片寬 480px、綠色頂線、三種身分分頁與淺色背景，並支援手機排版。

目前優先以 **1440 × 900 的瀏覽器內容區**驗收電腦版（2026-10-04 確認），卡片維持 480px 寬、水平置中、距離頂端 65px；較長的教師流程調整間距及掃描框，讓一般狀態與頁尾在此尺寸完整顯示。額外錯誤提示或展開預覽選單時允許正常捲動，不裁切內容。既有窄螢幕樣式先保留，手機、平板的精細設計及正式驗收留待後續。

以原有 ASP.NET Core 專案的 `wwwroot` 提供 HTML/CSS/JavaScript，無須安裝另一個前端框架。原本 Swagger、教師測試表單及授權 API 保留。

## 開啟

在 Visual Studio 啟動專案後，使用與 Swagger 相同的主機與連接埠，將 `/swagger` 換成 `/`：例如 `https://localhost:7127/`。保留既有 launchSettings，啟動時仍會先開 Swagger。

可直接開啟 `/?role=medical` 或 `/?role=teacher` 查看指定入口。

## 教師流程預覽

開啟 `/?role=teacher` 後：

1. 輸入非空白授權碼並按「驗證授權碼」，顯示驗證中動畫；約 1.2 秒後顯示「授權驗證尚未啟用」。不查核實際授權，不判定成功或失敗。
2. 驗證中可按返回取消示範，舊計時器不會再切換畫面。
3. 掃描 QR Code 按鈕進入掃描框示意；按「使用授權碼」返回輸入。未啟用相機或辨識器。
4. 展開頁尾「試做畫面預覽」，可查看驗證失敗。失敗原因不包含過期，符合不限時規格；這是示範，不代表任何實際授權被拒絕。
5. 各畫面可直接用 `/?role=teacher&view=verifying`、`view=failure`、`view=scan` 或 `view=unavailable` 開啟。

教師狀態的樣式與互動獨立放在 `wwwroot/css/teacher-access.css` 與 `wwwroot/js/teacher-access.js`。整合時可將示範計時器替換為正式 API 呼叫，再依伺服器結果顯示狀態。失敗原因目前僅為一般說明，不提供個案資訊。

## 前端分工與整合方式（2026-10-04 確認）

- A：醫療人員登入與登入驗證相關畫面。
- B：家長登入與家長端相關畫面。
- C（洪靜吟）：教師授權碼、QR Code 與授權驗證相關畫面。

三人先在各自分支完成，再共同整合。本分支目前保留三種入口的試做畫面供比對；不代表 C 接手 A、B 的前端工作。醫療入口需與 A 已完成的登入及驗證中畫面比對，再決定整合版本。這是前端分工，後端身分驗證與角色／權限責任仍依原分工。
