## 已確定的共同規則

- 使用者本人統整 schema 與 EF Core migration；其他組員提供模組及既有資料模型，不各自重建相同表。
- 個案暫由 A 的醫療端建立，正式責任仍待 A 核對；醫護決定問卷指派及複評輪次。
- 家長版與教師版使用各自固定的 questionnaireVersionId；改版不替換已指派任務。
- 家長手機 OTP 登入與個案綁定分開。醫護核實關係並登記手機，家長首次登入後使用指定個案／手機的一次性邀請碼；綁定成功後只需登入。
- 綁定邀請有期限、一次性、可撤銷；教師授權則不限時，不混用兩者。
- 已綁定家長建立教師授權；個管師目前不能代辦。每份問卷提交成功後該 task 完成，整組指定任務完成後 grant USED。
- 支援草稿；家長與教師提交後不能修改。醫護只在匯出的 Excel 離線修改，系統保留原始答案。
- 家長只能查看教師問卷完成狀態；草稿、撤銷或取消均不算正式完成。

## 已完成：本機 MySQL 與模型

最新進度：使用者在本機執行 `--apply --seed` 全部通過，九張核心表與 EF 歷程表已建立，虛構 seed 已保存並可跨連線查回。操作與限制見 [migration 設定說明](database/migration-setup.md)。教師開發 API 已改接 MySQL，使用者本機網站驗收待執行。

目標：建立可重現的開發資料庫與第一份 migration，先證明正式模型能保存、能查回；此步還不等於教師流程已串通。

1. 已確認本機 MySQL 8.0.46 可由 Workbench 連線，專案為 .NET 8、EF Core Design 8.0.13、Pomelo 8.0.3；接著實測專案連線，不需另裝一套 MySQL。
2. 建立獨立的本機開發資料庫與專案用連線，憑證放在本機設定或 user-secrets，不提交 Git。組員日後透過同一 migration 建立自己的開發資料庫。
3. 依共用規格建立九張核心表對應的 entities、DbSet 與關聯：cases、questionnaires、questionnaire_versions、case_questionnaires、teacher_grants、teacher_grant_tasks、teacher_sessions、questionnaire_drafts、questionnaire_responses。
4. 由使用者統整產生第一份 migration，檢查表名、唯一鍵、版本／角色及個案範圍外鍵，再套用本機開發資料庫。SQL 草案只作參考，不同時用手動 SQL 管理 schema。
5. 建立 Development 限定的可重複 seed：虛構幼兒、教師 SNAP-IV 已發布版本、指定任務；固定 seed UUID 保持一致，授權碼仍每次安全亂數產生且只保存雜湊。

驗證結果：獨立測試資料庫可由 migration 建立，使用者本機資料庫也已套用成功；同一 seed 重跑不新增重複資料，新 DbContext 能查回；編譯及模型關聯驗證通過。網站重啟後的教師操作驗收留到下一步。

## 已實作、待本機驗收：教師授權持久化

1. 將開發用教師授權建立改存 teacher_grants、teacher_grant_tasks，綁定資料庫內的個案與 PENDING 教師任務；授權碼只保存雜湊。
2. 驗證授權時查 MySQL，會話保存到 teacher_sessions；每次受保護請求都核對授權及會話狀態。
3. 工作台從 case_questionnaires 與 questionnaire_versions 查回指定任務、固定版本及題目，取代記憶體固定資料。
4. 撤銷與登出更新資料庫；撤銷後既有會話也不能繼續查詢或填答。

驗收：建立授權後重啟網站，原授權碼仍能重新驗證取得任務；撤銷後重啟仍被拒絕；無效碼被拒絕。全部任務完成後 USED 的實際驗收，等正式提交功能完成時一起測試。本步仍是 Development 虛構授權，不代表正式家長同意已完成。
